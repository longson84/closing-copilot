# Spec — "Closing Copilot" (working name)

AI Builder Cup 2026 · Future of Work & Enterprise Productivity · Deadline: submission ~18h from 2026-10-18 session start.

## Problem
Singapore new-launch property agents juggle hard legal deadlines per deal (OTP → S&P → exercise →
stamp duty → 15% downpayment). Missed dates cost buyers their booking fee or incur late stamp-duty
penalties; ID handling must satisfy CEA customer due diligence and PDPA. Agents track this in
spreadsheets and chat apps.

## Users
- **Sales agent** (primary): registers bookings, uploads documents, asks the copilot what to do next.
- **Sales manager** (secondary, demo-only): "which deals are at risk this week?"

## Core flow (the demo)
1. **Register booking** — agent uploads buyer NRIC/passport image. Document AI OCR → Gemini structured
   extraction → customer record created. NRIC masked in UI (S****567D). CDD checklist auto-filled.
2. **Deal stages** (SG new launch, developer sale), deadlines computed from the OTP date:
   1. Booking — OTP issued, 5% booking fee (Day 0)
   2. CDD complete
   3. S&P delivered by developer's solicitor (≤ ~2 weeks after OTP)
   4. S&P signed & returned / exercised (≤ ~3 weeks after S&P delivered)
   5. Stamp duty BSD/ABSD paid (≤ 14 days after S&P signed)
   6. 15% balance downpayment (≤ ~8 weeks after OTP)
   7. Progressive payments → TOP / keys (after-sales begins)
   *(Timelines to be verified against a SG conveyancing source before demo.)*
3. **Stage document checks** — agent uploads OTP / S&P / receipt; the agent cross-checks against the
   customer record and prior docs (name mismatch, wrong 5% amount, dates) and advances the stage.
4. **Copilot chat** — "What do I need to do today?", "Is Tan's deal on track?", "Draft a reminder to
   the buyer". Stamp duty via a deterministic calculator tool; Gemini explains.
5. **After-sales suggestions** — personalised from buyer profile (investor/owner-occupier, residency,
   family) + dates: progress-payment reminders, defects-liability inspection, loan lock-in review,
   tenant search before TOP, referral ask.

## Agent tools
`extract_identity_document`, `check_stage_document`, `get_deal`, `list_deals_needing_action`,
`advance_stage`, `calc_stamp_duty` (code, not LLM), `draft_customer_message`, `suggest_followups`.

## Guardrails
- Never invent amounts/dates — numbers come from tools or documents only.
- Never reveal full NRIC in chat or logs; masked everywhere except the stored record.
- Stage advance requires the agent (human) to confirm.
- English only.

## Tech
- **ADK TypeScript** (`@google/adk` 2.3.x) — single LlmAgent with function tools; hand-scaffolded
  (agents-cli has no TS template).
- Gemini on Vertex AI (latest available Flash model in chosen region), Document AI OCR processor.
- Firestore for deals/customers; Cloud Storage for uploaded docs.
- Hono API + React (Vite) single Cloud Run service. Seeded fake data only — no real PII.

## Deliverables
Deployed Cloud Run URL · public 3-min video · PDF deck · public repo · all English.

## Out of scope (today)
Real scheduled notifications, auth/SSO, multi-tenant, resale flow, vector RAG, BigQuery.

## Eval
5–8 ADK eval cases (mismatch detection, deadline question, stamp duty, PII masking refusal,
follow-up suggestions) run before deploy.
